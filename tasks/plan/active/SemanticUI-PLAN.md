## Exception Registry
File: `tests/config/semantic-exceptions.json`  
Required fields per exception:
1. `file`
2. `rule`
3. `owner`
4. `expiry_date` (ISO date)
5. `ticket`

Additional required controls:
1. Exception must include `created_at` and `rationale`.
2. Expired exception is hard fail.
3. Section cannot freeze with open expired exceptions.
4. New exception in a batch requires explicit reason in batch report.

## Test Scenarios and Pass/Fail Criteria
1. Batch modifies modern `v2/<section>` pages and `run-pr-checks` must detect/validate them (no silent skip).
2. Any new `/v2/pages/` reference in touched files fails batch gate.
3. Any docs.json missing route in strict mode fails.
4. Any broken internal link/import in touched files fails.
5. Generated index page without frontmatter does not fail metadata contract (carveout), but broken links still fail.
6. Expired exception entry fails batch immediately.
7. Locale parity batch must generate valid route-map/report artifacts with no validation failures.
8. Final full audit and runtime smoke complete with zero blocking errors.
