# Livepeer Documentation

Source repository for [docs.livepeer.org](https://docs.livepeer.org). Built on [Mintlify](https://mintlify.com/) (MDX). Contains the published docs, the component library, operations tooling, CI pipelines, generated-content pipelines, and the internal governance system.

This is more than a docs site — it is a self-documenting docs **platform**. The repo includes its own component library, generators that auto-build catalogs and indexes from source, AI skills for content workflows, OG-image and asset pipelines, render-verification harnesses, an internal docs-about-docs layer (`docs-guide/`), and a canonical wrapper pattern that lets the same content surface in multiple navigation locations without duplication.

## Features

| Capability | How it works |
|---|---|
| **Multi-tab IA** | Audience-anchored content split across About / Home / Developers / Gateways / Orchestrators / Delegators / Community / Resource HUB / Solutions tabs. Each tab has its own navigation. |
| **Resource HUB** | Canonical aggregation layer at `v2/resources/`. Hosts the unified glossary, FAQ, troubleshooting, technical references (contract addresses, protocol parameters, go-livepeer reference, APIs & SDKs, network data), changelogs, knowledge hub, and full documentation guide. |
| **Composable wrapper pattern** | Canonical content lives once at `snippets/composables/pages/canonical/*.mdx`. Audience tabs and the Resource HUB each list thin wrapper MDX files that import and render the canonical. Edit once, propagate everywhere. |
| **Hand-authored aggregations** | Where content is collated from multiple audience sources (FAQ, Guides, Troubleshooting), the HUB hosts a hand-organised canonical that preserves source Q&A verbatim. |
| **Generated content pipelines** | Contract addresses, AI APIs, CLI-HTTP APIs, SDK reference, changelogs, glossaries — all generated by scripts under `operations/scripts/generators/` from canonical data sources. |
| **AI integrations** | AI-discoverable companion JSON for every tier-2 page, `sitemap-ai.xml`, `llms.txt`, AI-first OG images, and per-page agent context cards. |
| **Agent skills** | 30+ AI skills under `ai-tools/ai-skills/` provide reusable workflows (research, thread anchoring, content review, propagation, gap analysis, etc.). |
| **Governance enforcement** | `.githooks/pre-commit` runs hard gates (MDX validation, allowlist guards, v1 frozen-file protection). CI workflows run soft checks (style, copy, components, broken links). |
| **Local dev with scoped restart** | `node operations/scripts/dispatch/governance/server-lifecycle.js restart v2/<tab>` boots a scoped Mintlify dev server in ~2 minutes (vs ~10 minutes cold). |

The canonical wrapper pattern is foundational. Reference exemplar: [`snippets/composables/pages/canonical/livepeer-contract-addresses.mdx`](snippets/composables/pages/canonical/livepeer-contract-addresses.mdx) with consumer wrappers at [`v2/about/resources/reference/livepeer-contract-addresses.mdx`](v2/about/resources/reference/livepeer-contract-addresses.mdx) and three other paths.

## Quick start

There is no root `package.json`. The CLI handles all dependency installation.

```bash
git clone https://github.com/livepeer/docs.git && cd docs
git checkout docs-v2

bash tools/lpd setup --yes   # installs deps, hooks, PATH link
lpd dev                      # starts dev server on port 3333
```

Mintlify is opt-in during setup. To include it: `bash tools/lpd setup --yes --with-mintlify` (or `npm i -g mintlify` manually).

Root governance is explicit. Only approved root contracts and subsystem roots belong at repo root. `ai-tools/` is an intentionally governed root subsystem, and the ratified AI-first public root artifacts are `docs-index.json`, `llms.txt`, and `sitemap-ai.xml`.

## Contributing

1. Read the [authoring guide](v2/resources/documentation-guide/copy-style/authoring-guide.mdx) and [style guide](v2/resources/documentation-guide/copy-style/style-guide.mdx).
2. Install hooks: `bash .githooks/install.sh` (or `lpd hooks install`).
3. Branch from `docs-v2`, run `lpd dev` to preview, then open a PR against `docs-v2`.

Full contributing docs: [`docs-guide/contributing/contributing.mdx`](docs-guide/contributing/contributing.mdx)

**Contribution model in one screen:** read the [Contributing tab in Resource HUB](v2/resources/documentation-guide/contributing/contributing.mdx) for the canonical workflow. The HUB wraps every governance/contributor page from `docs-guide/`, so you can browse the entire contributor knowledge base inside the docs site without switching tabs.

## Quality gates

### Pre-commit (9 hard gates)

The `.githooks/pre-commit` hook blocks commits that fail MDX validation, docs.json redirect integrity, v1 frozen-file guards, allowlist protection, and Codex branch isolation, among others.

Pull requests trigger test suites, broken-link checks, browser rendering sweeps, OpenAPI validation, docs-guide catalog checks, and more.

## Source-of-truth contract

- Code and tests are source of truth for behaviour.
- `docs-guide/` is source of truth for internal capability navigation.
- `README.md` is high-level orientation and link hub.
- Generated indexes must be regenerated, not hand-edited:

```bash
node operations/scripts/generators/governance/catalogs/generate-docs-guide-indexes.js --write
node operations/scripts/generators/governance/catalogs/generate-docs-guide-pages-index.js --write
node operations/scripts/generators/governance/catalogs/generate-docs-guide-components-index.js --write
node operations/tests/unit/script-docs.test.js --write --rebuild-indexes
```
