# Community help wanted

The Livepeer docs repo is **ownerless by design**: every governed surface declares a canonical source, a deterministic validator, an exact repair command, and a single gate layer. When the contract is complete, an OSS contributor – or an AI agent acting on their behalf – can correct routine drift without staff context. This page is the standing queue of open opportunities.

Eighty-plus items are open across six feature domains. Each has a file path, an acceptance criterion, a priority, and a rough effort estimate. Many are excellent first PRs.

<Note>
**Where this list comes from.** Session-1 of the docs-as-infrastructure consolidation produced seven product-forward feature audits at [`workspace/thread-outputs/repo-docs-consolidation/`](https://github.com/livepeer/docs/tree/docs-v2/workspace/thread-outputs/repo-docs-consolidation). The synthesis is at [`00-SYNTHESIS.md`](https://github.com/livepeer/docs/blob/docs-v2/workspace/thread-outputs/repo-docs-consolidation/00-SYNTHESIS.md). This page is the curated, deduplicated index suitable for community contribution.
</Note>

## How to claim an opportunity

<Steps>
  <Step title="Open an issue using the right template">
    `.github/ISSUE_TEMPLATE/` ships nine templates. Pick the one closest to the work – content request, docs page issue, feature request, tooling/CI issue. The template auto-applies `area:*` and `priority:*` labels.
  </Step>
  <Step title="Reference this page in the issue body">
    Quote the specific opportunity and link to it. Example: "I'm picking up `[AI-1] Wire llms.txt regen to CI` from [community-help](/docs-guide/contributing/community-help)."
  </Step>
  <Step title="Read the acceptance criteria carefully">
    Each entry below names the file path, the validator that must pass, and the expected output. The PR is "done" when the acceptance criterion is met, not just when the change compiles.
  </Step>
  <Step title="Submit a PR against `docs-v2`">
    Follow the [contributor quickstart](/docs-guide/index#contributor-quickstart). The PR template auto-fills with Required Reading based on changed paths. CI runs the same validators the acceptance criterion names.
  </Step>
</Steps>

<Tip>
**Excellent first PRs** are tagged `[FIRST-PR]` below. They are mechanical, well-bounded, with clear acceptance criteria and a small blast radius.
</Tip>
