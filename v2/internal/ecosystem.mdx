This page maps the Livepeer ecosystem from the documentation's perspective. It is the internal companion to [Personas](/v2/internal/overview/personas) and the public [About Livepeer](/v2/about) tab. Stakeholder data is sourced from the RFP work audit (Part 2.2) and confirmed in `v2/internal/rfp/reports/livepeer-docs-v2-report.md`.

## Ecosystem at a glance

Livepeer is a protocol, a network, and a product surface. The documentation serves four primary audiences and several secondary ones. Each audience maps to a specific tab and a specific maintenance contract.

| Audience | Primary tab | Why they read these docs |
| --- | --- | --- |
| Developers (builders integrating Livepeer) | [`v2/developers/`](/v2/developers) | Build on Livepeer video and AI capabilities through SDKs, APIs, and Gateways. |
| Gateway operators | [`v2/gateways/`](/v2/Gateways) | Deploy and operate a self-hosted Gateway against the network. |
| Orchestrators | [`v2/orchestrators/`](/v2/Orchestrators) | Run a transcoding or AI compute node and participate in the Active Set. |
| Delegators | [`v2/delegators/`](/v2/Delegators) | Stake LPT, choose Orchestrators, monitor rewards. |
| Solutions integrators | [`v2/solutions/`](/v2/solutions) | Evaluate or integrate ecosystem products (Studio, Daydream, Streamplace, Frameworks, Embody). |
| Community contributors and OSS readers | [`v2/community/`](/v2/community), [`v2/resources/`](/v2/resources) | Find showcase work, changelog, glossary, and references. |
| Foundation, Inc, SPE teams | [`v2/internal/`](/v2/internal) (this tab) | Coordinate strategy, RFP record, governance. |

### Infrastructure dependencies

The documentation has hard data dependencies on the following external surfaces:

- Arbitrum One and Ethereum Mainnet on-chain state (for contract addresses verification).
- `livepeer/protocol` (smart contract source).
- `livepeer/go-livepeer` releases (binary version data).
- `livepeer/ai-runner` and `livepeer/ai-worker` (AI worker OpenAPI specs).
- CoinGecko (LPT ticker data).
- Discourse forum.livepeer.org, Ghost blog, GitHub (releases and discussions), Discord, RSS, YouTube, Luma (community feeds).
- Google Sheets + Discord (project showcase submission pipeline).
- Mintlify (hosted publishing platform and chat assistant).

Each dependency is documented as a data integration family in [Data Integrations](/docs-guide/features/data-integrations). When an upstream changes contract, the integrator script is the surface to update, not the rendered pages.

## How the ecosystem maps to docs surfaces

The documentation distinguishes three audience surfaces deliberately. Bleed between them is governance debt, not feature work.

| Surface | Audience | Canonical home |
| --- | --- | --- |
| Contributor + engineering canonical | Maintainers, contributors, AI agents working on this repo | [`docs-guide/`](/docs-guide/index) |
| Public reader-facing | Anyone reading docs.livepeer.org | `v2/` tabs (developers, Gateways, Orchestrators, Delegators, solutions, resources, community, about, home) |
| Project-internal | Foundation, Inc, SPEs working on the documentation engagement | `v2/internal/` (this tab) |
