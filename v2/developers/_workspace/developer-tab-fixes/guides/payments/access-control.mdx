By default, Livepeer streams and assets are publicly playable. Two playback policy types restrict access: `jwt` (your backend issues signed tokens) and `webhook` (Livepeer calls your endpoint on each playback request).

<CustomDivider />

## JWT Signing Keys

A signing key is an ES256 keypair. The private key signs JWTs your application issues; the public key is registered with Livepeer for validation. Up to 10 signing keys can be active at once.

Create a signing key:

```javascript
import { Livepeer } from 'livepeer';

const client = new Livepeer({ apiKey: process.env.LIVEPEER_API_KEY });

const { signingKey } = await client.accessControl.createSigningKey();

// Save these: privateKey is shown only at creation
console.log(signingKey.id);
console.log(signingKey.publicKey);   // base64-encoded public key
// signingKey.privateKey is available only in this response
```

Apply the JWT playback policy to a stream or asset at creation:

```javascript
const { stream } = await client.stream.create({
  name: 'gated-stream',
  profiles: [...],
  playbackPolicy: { type: 'jwt' },
});
```

Or apply it to an existing asset:

```javascript
await client.asset.update(asset.id, {
  playbackPolicy: { type: 'jwt' },
});
```

**Issuing JWTs from your backend:**

```javascript
import { SignJWT, importPKCS8 } from 'jose';

const privateKeyPem = Buffer.from(
  process.env.ACCESS_CONTROL_PRIVATE_KEY,
  'base64',
).toString('utf-8');

const privateKey = await importPKCS8(privateKeyPem, 'ES256');

const jwt = await new SignJWT({ sub: playbackId })
  .setProtectedHeader({ alg: 'ES256' })
  .setExpirationTime('1h')
  .sign(privateKey);
```

Pass the JWT to the `@livepeer/react` Player:

```jsx
import * as Player from '@livepeer/react/player';

<Player.Root src={src} jwt={jwt}>
  <Player.Container>
    <Player.Video />
  </Player.Container>
</Player.Root>
```

For non-Player clients, pass the JWT as the `Livepeer-Jwt` header on WebRTC SDP negotiation or HLS playback requests. For MP4 playback, use the `jwt` query parameter.

## Webhook Playback Policy

The webhook policy calls your endpoint on every playback request. Return 200 to allow playback; return any 4xx to deny.

Register a webhook endpoint:

```javascript
const webhook = await client.webhook.create({
  name: 'playback-gate',
  url: 'https://your-app.example.com/livepeer-playback-auth',
  events: [],
  sharedSecret: process.env.WEBHOOK_SECRET,
});
```

Apply to a stream or asset:

```javascript
const { stream } = await client.stream.create({
  name: 'webhook-gated',
  profiles: [...],
  playbackPolicy: {
    type: 'webhook',
    webhookId: webhook.webhook.id,
    webhookContext: { tier: 'premium' },
  },
});
```

The webhook receives a POST with the request context including the `webhookContext` you configured. Verify the `Livepeer-Signature` header using the shared secret before processing.

<CustomDivider />

## API Key Types

The Livepeer API uses two key types with different security models:

- **Server-side API keys** (default): usable only from backend services. These have full account access and must never be exposed in frontend code.
- **CORS-enabled API keys**: allow frontend requests but restrict which operations are permitted. Because CORS keys are visible to clients, the `playbackId` of gated content must be kept secret from unauthorised users when using CORS keys.

For access-controlled content, issue JWTs from a backend endpoint that verifies user authorisation before signing. Do not use CORS keys to create or modify playback-gated streams or assets from the browser.

<CustomDivider />

JWT-based access control is the recommended path for most applications. Webhook-based control is for cases where authorisation logic is too complex for a signed token.
