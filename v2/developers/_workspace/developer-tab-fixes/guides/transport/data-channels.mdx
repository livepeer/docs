Trickle data channels carry non-media data alongside video and audio streams. They use the same publish/subscribe model as media channels but transport text, JSON, or binary payloads instead of frames.

Data channels were added in ComfyStream Phase 4 to support multimodal outputs: a pipeline can produce video frames on the media channel and text transcriptions or structured metadata on a data channel simultaneously.

<CustomDivider />

## Data channel architecture

A `live-video-to-video` session can include multiple channels:

| Channel | Content | Direction |
|---|---|---|
| Media publish | Video/audio frames | Gateway to orchestrator |
| Media subscribe | Processed video/audio | Orchestrator to gateway |
| Control | Parameter updates (JSON) | Gateway to orchestrator |
| Data output | Text, JSON, or binary | Orchestrator to gateway |

The data output channel uses a separate trickle subscribe URL. The `LiveVideoToVideo` object exposes it via `events_url` when the pipeline declares data output support.

<CustomDivider />

## Using data channels in PyTrickle

```python
from pytrickle import TrickleSubscriber

# Subscribe to data channel output
data_sub = TrickleSubscriber(url=job.events_url)

async for segment in data_sub:
    payload = segment.data.decode('utf-8')
    # payload is typically JSON: {"type": "transcription", "text": "hello world", "timestamp": 1.5}
    event = json.loads(payload)
    print(f"[{event['timestamp']}] {event['text']}")
```

Data channel segments follow the same sequence numbering as media segments but on a separate URL. They can arrive at a different rate than media frames (e.g., one transcription result per spoken phrase, not per video frame).

<CustomDivider />

## Common data channel use cases

**Real-time transcription:** A ComfyStream workflow with a Whisper audio node outputs transcription text on the data channel while the processed video continues on the media channel.

**Structured metadata:** A vision model produces per-frame labels, bounding boxes, or scene classifications as JSON objects on the data channel.

**Pipeline telemetry:** Frame processing latency, queue depth, and GPU utilisation metrics published by the pipeline for the gateway's monitoring system.
