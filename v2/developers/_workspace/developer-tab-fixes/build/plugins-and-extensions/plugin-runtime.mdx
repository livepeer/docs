The NaaP plugin runtime is the execution environment inside the shell application. Understanding the lifecycle helps when debugging mount failures, permission errors, or inter-plugin communication issues.

<CustomDivider />

## Plugin lifecycle

1. **Registry lookup:** The shell reads the installed plugin list from the database
2. **UMD fetch:** The shell fetches each plugin's UMD bundle from the registry CDN
3. **Mount:** The shell calls the plugin's default export with a `ShellContext` object
4. **Render:** The plugin renders its React components into the shell's content area
5. **Unmount:** On navigation away, the shell calls the plugin's cleanup function

```typescript
// What the shell does internally (simplified)
const module = await import(pluginBundleUrl);
const plugin = module.default;

// Mount with ShellContext
plugin.mount(document.getElementById('plugin-root'), shellContext);

// Later: unmount
plugin.unmount();
```

<CustomDivider />

## ShellContext services

Every plugin receives the same `ShellContext` object on mount:

| Service | Purpose |
|---|---|
| `auth` | Current user, roles, permissions, login/logout |
| `navigate` | Client-side routing within the portal |
| `eventBus` | Publish/subscribe for inter-plugin communication |
| `theme` | Current theme (dark/light), colour tokens |
| `notifications` | Toast notifications (success, error, info) |
| `integrations` | AI, storage, and email service connectors |
| `logger` | Structured logging with plugin context |
| `permissions` | Permission checking for the current user |
| `tenant` | Multi-tenant context (if enabled) |
| `team` | Team context (if enabled) |

Access these through the SDK hooks:

```typescript
import { useShell, useAuth, useEventBus } from '@naap/plugin-sdk';

export function MyPlugin() {
  const { navigate, notifications } = useShell();
  const { user, hasPermission } = useAuth();
  const eventBus = useEventBus();
  
  if (!hasPermission('network:read')) {
    return <div>Permission denied</div>;
  }
  // ...
}
```

## Inter-plugin communication

Plugins communicate through the event bus, not by direct import. This keeps plugins decoupled:

```typescript
// Plugin A: publish an event
eventBus.emit('capacity:updated', { gpu: 4, available: 2 });

// Plugin B: subscribe to events
eventBus.on('capacity:updated', (data) => {
  console.log(`GPU available: ${data.available}/${data.gpu}`);
});
```

Event names follow the pattern `{plugin-id}:{event-name}`. Subscribe to `*` to receive all events (useful for debugging).
