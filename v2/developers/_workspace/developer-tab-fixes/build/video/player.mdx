The `@livepeer/react` package (`livepeer/ui-kit`) provides React primitives for video playback and broadcasting. The `Player` component handles adaptive bitrate playback over HLS and low-latency WebRTC, surface-testing across browsers, and WAI-ARIA accessibility with keyboard shortcuts.

<CustomDivider />

## Installation

```bash
npm install @livepeer/react
```

Current version: 4.3.6. The package requires React 17 or React 18.

<CustomDivider />

## Basic Player

Pass a `playbackId` from a Livepeer stream or VOD asset:

```jsx
import { Player } from '@livepeer/react';

export function VideoPlayer({ playbackId }) {
  return (
    <Player
      playbackId={playbackId}
      autoPlay
      muted
    />
  );
}
```

The `playbackId` comes from:
- `stream.playbackId` when a stream is created via the Livepeer API
- `asset.playbackId` when a VOD asset finishes transcoding

The Player resolves the playback URL, negotiates the best transport (WebRTC for low-latency live streams, HLS for VOD and standard live), and handles adaptive bitrate switching automatically.

<CustomDivider />

## Key Props

| Prop | Type | Default | Description |
|---|---|---|---|
| `playbackId` | string | required | Livepeer playback ID |
| `src` | string | none | Direct HLS or WebRTC URL (alternative to `playbackId`) |
| `autoPlay` | boolean | `false` | Start playback immediately |
| `muted` | boolean | `false` | Mute audio (required for autoPlay in most browsers) |
| `loop` | boolean | `false` | Loop the video (VOD only) |
| `showTitle` | boolean | `true` | Show stream/asset name overlay |
| `showPipButton` | boolean | `false` | Show picture-in-picture button |
| `controls` | object | none | Override default control visibility |
| `theme` | object | none | Style overrides for player chrome |
| `lowLatency` | boolean \| `"force"` | `true` | Prefer WebRTC for live streams; `"force"` disables HLS fallback |

## Low-Latency WebRTC

For live streams, the Player prefers WebRTC when available, falling back to HLS. WebRTC delivery provides sub-second glass-to-glass latency compared to the 5-15 second latency of standard HLS.

```jsx
<Player
  playbackId={playbackId}
  lowLatency="force"
  autoPlay
  muted
/>
```

`lowLatency="force"` disables the HLS fallback path. Use this only when you are certain the WebRTC path is available and acceptable to all viewers.

## Custom ICE Servers

From `@livepeer/react` 4.3.0, custom ICE servers can be passed for WebRTC negotiation:

```jsx
<Player
  playbackId={playbackId}
  iceServers={[
    { urls: 'stun:stun.example.com:3478' },
    {
      urls: 'turn:turn.example.com:3478',
      username: 'user',
      credential: 'pass',
    },
  ]}
/>
```

## Broadcast Component

The `Broadcast` component provides WebRTC publishing from the browser:

```jsx
import { Broadcast } from '@livepeer/react';

export function StreamBroadcaster({ streamKey }) {
  return (
    <Broadcast
      streamKey={streamKey}
      controls={{ camera: true, microphone: true }}
    />
  );
}
```

Pass the stream key from a Livepeer stream object. The Broadcast component negotiates a WebRTC connection to the Livepeer ingest endpoint and publishes the camera/microphone feed.

<CustomDivider />

The Player handles ABR selection, HLS parsing, and WebRTC fallback automatically. Pass a `playbackId` from a stream or asset and the component does the rest.
