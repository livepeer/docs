The `@muxionlabs/byoc-sdk` provides CLI tooling for the BYOC container development workflow. Source at [`muxionlabs/byoc-sdk`](https://github.com/muxionlabs/byoc-sdk).

<CustomDivider />

## CLI commands

| Command | Description |
|---|---|
| `byoc init` | Scaffold a new BYOC container project |
| `byoc dev` | Start local development server with trickle test harness |
| `byoc build` | Build the Docker image with CUDA base and model weights |
| `byoc test` | Run the container against a local trickle server |
| `byoc deploy` | Register the container with an orchestrator's `aiModels.json` |

<CustomDivider />

## Project structure

`byoc init` generates:

```
my-pipeline/
  ├── src/
  │   └── pipeline.py          # FrameProcessor implementation
  ├── Dockerfile               # Multi-stage CUDA build
  ├── requirements.txt         # Python dependencies
  ├── aiModels.json            # Capability registration template
  ├── health.py                # /health endpoint
  └── docker-compose.yml       # Local development compose
```

The scaffold includes a working FrameProcessor that passes frames through unchanged. Replace `process_frame()` with your model logic.
