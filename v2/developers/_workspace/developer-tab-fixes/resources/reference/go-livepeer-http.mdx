go-livepeer exposes an HTTP API when running in broadcaster (gateway) or orchestrator mode. The API serves two purposes: routing inference and transcoding requests, and providing node status and configuration.

<CustomDivider />

## Broadcaster (gateway) endpoints

| Endpoint | Method | Description |
|---|---|---|
| `/{pipeline}` (e.g. `/text-to-image`) | POST | Route an AI inference request to an orchestrator |
| `/live-video-to-video` | POST | Start a real-time AI session |
| `/live/{streamKey}` | RTMP | Accept RTMP ingest for a stream key |
| `/stream/{manifestId}.m3u8` | GET | Serve the HLS manifest for a transcoded stream |
| `/status` | GET | Node status (connected orchestrators, active streams) |

AI inference endpoints proxy through to the selected orchestrator and return the response. The broadcaster handles orchestrator selection, payment, and retry logic internally.

<CustomDivider />

## Orchestrator endpoints

| Endpoint | Method | Description |
|---|---|---|
| `/status` | GET | Node status (capabilities, active sessions, GPU info) |
| `/getOrchestrator` | POST | gRPC-over-HTTP for GetOrchestratorInfo |
| `/registeredTranscoders` | GET | List of registered transcoder workers |

<CustomDivider />

## livepeer_cli

`livepeer_cli` is a terminal-based interactive tool that connects to the go-livepeer HTTP API for node management:

```bash
livepeer_cli -host 127.0.0.1 -http 7935
```

The CLI provides options for: viewing node status, initiating reward calls (orchestrators), setting service URI, depositing and withdrawing from TicketBroker, and viewing orchestrator configuration.
