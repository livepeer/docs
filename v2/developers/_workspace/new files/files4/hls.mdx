Livepeer outputs ABR HLS for both live streams and VOD assets. The output is a standard HLS manifest compatible with any HLS player. The `@livepeer/react` Player handles ABR selection automatically; for non-React environments, `hls.js` or any ABR-capable player consumes the manifest directly.

<CustomDivider middleText="Manifest Structure" />

## ABR Manifest

The top-level HLS manifest (`index.m3u8`) lists all transcoded renditions. Each rendition has a separate playlist with segment references. A player requests the top-level manifest first, then selects a rendition playlist based on available bandwidth.

```
#EXTM3U
#EXT-X-VERSION:3
#EXT-X-STREAM-INF:BANDWIDTH=3000000,RESOLUTION=1280x720
720p/index.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=1000000,RESOLUTION=640x360
360p/index.m3u8
```

The `BANDWIDTH` field is the rendition's target bitrate in bits per second. The player switches renditions dynamically as network conditions change.

## Playback URL Format

For assets created via the Livepeer API, the `playbackUrl` field on the asset or stream object points to the top-level manifest:

```
https://livepeercdn.com/hls/<playbackId>/index.m3u8
```

For direct go-livepeer broadcaster output, the HLS manifest is at:

```
http://<httpAddr>/stream/<streamName>.m3u8
```

For ABR playback, use the top-level manifest URL. Individual rendition manifests are at:

```
http://<httpAddr>/stream/<streamName>/<profileName>.m3u8
```

## Short-Form MP4 Playback

For VOD assets under 2 minutes, the Livepeer API provides short-form MP4 playback URLs alongside the HLS manifest. MP4 URLs allow CDNs and players to cache short videos for instant time-to-first-frame on subsequent plays.

Short-form MP4 availability is indicated in the playback info response. The `@livepeer/react` Player uses MP4 URLs automatically when available.

<CustomDivider middleText="Live Stream HLS" />

## Live Stream Output

For live streams, the HLS manifest is a live playlist: it contains a sliding window of recent segments, updated as new segments are transcoded. The go-livepeer broadcaster appends segments to the manifest as they are returned from orchestrators.

Latency for live HLS is determined by segment duration and the number of segments the player buffers. Default go-livepeer segment configuration results in approximately 6-15 seconds of latency end-to-end. For sub-second latency, use the WebRTC path instead.

<CustomDivider middleText="Player Integration" />

## Player Integration

**@livepeer/react Player:** Pass the `playbackId` from a Livepeer asset or stream and the component handles HLS and WebRTC automatically:

```jsx
import { Player } from '@livepeer/react';
<Player playbackId={playbackId} />
```

**hls.js (non-React):**

```javascript
import Hls from 'hls.js';

const video = document.getElementById('video');
const src = 'https://livepeercdn.com/hls/<playbackId>/index.m3u8';

if (Hls.isSupported()) {
  const hls = new Hls();
  hls.loadSource(src);
  hls.attachMedia(video);
} else if (video.canPlayType('application/vnd.apple.mpegurl')) {
  // Safari native HLS
  video.src = src;
}
```

Safari plays HLS natively; all other browsers require hls.js.
