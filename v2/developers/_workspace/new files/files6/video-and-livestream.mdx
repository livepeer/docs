Livepeer provides GPU-backed video transcoding and delivery infrastructure for live streams and video on demand. The network handles the compute-intensive transcoding step: converting a single-quality RTMP stream into multiple renditions at different bitrates, while leaving ingest sourcing and viewer-facing playback under the developer's control.

<CustomDivider middleText="Video Pipeline" />

## The Video Pipeline

A live video session on Livepeer passes through four stages:

**1. Ingest:** An encoder (OBS, FFmpeg, a browser via WebRTC/WHIP) pushes a single-quality video stream to a gateway's RTMP endpoint. The gateway receives the stream, segments it into short chunks, and prepares segments for submission to the network.

**2. Transcoding:** The gateway routes segments to one or more orchestrators in the active set. Orchestrators run go-livepeer with GPU transcoding hardware and return a set of renditions at the profiles requested. Payment for each transcoded segment is made via probabilistic micropayment tickets.

**3. Packaging:** The gateway assembles the transcoded segments into an ABR HLS manifest. The manifest lists all renditions; players select the appropriate quality based on available bandwidth.

**4. Delivery:** The HLS manifest and segments are served from the gateway or a CDN. The `@livepeer/react` Player consumes the manifest and handles adaptive bitrate selection and WebRTC fallback automatically.

## Transcoding Profiles

Transcoding profiles define the output renditions. Each profile specifies resolution, bitrate, framerate, and H.264 encoder profile. The network produces all requested renditions in parallel.

Livepeer includes a set of named presets (`P720p30fps16x9`, `P480p30fps16x9`, etc.) usable directly. Custom profiles are specified as objects with `name`, `width`, `height`, `bitrate`, and `fps` fields. Bitrate is in bits per second.

The HLS manifest's `BANDWIDTH` attribute for each rendition reflects the configured bitrate, enabling ABR players to switch renditions appropriately.

## Access Points

Three paths exist for video developers, depending on how much infrastructure they want to operate:

**Video REST API:** The managed API handles stream lifecycle, storage, webhook delivery, and playback URL generation. No node operation required. Accessed via the `livepeer` SDK (JS, Python, Go, Java) or direct HTTP.

**go-livepeer broadcaster:** Running a local broadcaster node gives direct network access with custom orchestrator selection, pricing control, and RTMP-to-HLS without a managed API layer.

**LPMS:** The embeddable Go library for applications that need RTMP ingest and transcoding as a library component rather than a standalone service.
