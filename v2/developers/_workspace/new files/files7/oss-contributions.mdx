## go-livepeer Contribution Process

go-livepeer is the most active node software repository. Contributions follow a standard GitHub PR workflow with a few project-specific conventions.

**Commit structure:** Commits are logically grouped. The project uses fixup commits and autosquashing during rebase. Avoid merge commits; rebase against the upstream branch before opening a PR.

**Changelog entries:** Every PR that affects behaviour requires a changelog entry in `CHANGELOG.md`. Classify the entry by node type: General, Broadcaster, Orchestrator, or Transcoder. Breaking changes go in the "Breaking changes" section. Pending deprecations go in "Upcoming changes". Include the PR number (e.g. `\#3682`) rather than a full URL.

**Maintainer response:** Expect a response within 7 days. If you have not heard anything, ping the PR thread.

**Issue labels in use:**

| Label | Meaning |
|---|---|
| `help wanted` | Maintainers want external contributors on this |
| `good first issue` | Accessible scope for new contributors |
| `status: triage` | Not yet evaluated by maintainers |
| `status: needs-owner` | Valid issue without an assigned contributor |
| `priority: medium` | Scheduled after higher-priority work |

## Documentation Contributions

The documentation repository (`livepeer/docs`, branch `docs-v2-dev`) is the lowest-friction entry point for first contributions. Changes do not require Go or Python knowledge and the review cycle is fast.

**Standards that apply to all doc contributions:**

- UK English throughout (colour, behaviour, analyse, etc.)
- No em-dashes in narrative prose
- JSX comments only (`{/* */}`); no HTML comments
- No Studio-framing in pages under `v2/developers/`; these pages document network-direct access, not managed APIs
- All technical claims verified against a canonical source (go-livepeer, ai-runner, protocol repo) before inclusion

The documentation standards are defined in the skills directory of the repo (`/ai-tools/ai-skills/`).

## Funded Contribution Paths

Two mechanisms fund OSS contributions beyond goodwill:

**Network Engineering SPE: Retroactive grants:** Submit completed work to the Livepeer Forum for retroactive payment in the $2k–$20k range. Includes GitHub contributions, tooling, documentation. See <LinkArrow href="/v2/developers/opportunities/grants-and-programmes" label="Grants and Programmes" newline={false} />.

**Network Engineering SPE: RFPs:** Apply to published RFPs for scoped engineering work. Some RFPs target go-livepeer improvements, orchestrator tooling, or developer onboarding infrastructure.
